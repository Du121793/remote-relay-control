# 後端管理台版面說明

`tools/backend-test/dashboard.html` 是後端管理台的參考版面。它不是最終 React 版，但必須保留完整的管理流程與可讀性。

## 設計目標

- 讓管理者能直接操作多群組、多節點。
- Relay、保護、排程器的功能分區要和 MCU Web 一致。
- 後端獨有功能可以保留，但不要把 MCU 不需要的資訊硬塞到一般使用者視角。
- 所有寫入操作要有等待狀態，不要只顯示「已送出」。
- 手機版要能用，不能讓按鈕、卡片或表格互相覆蓋。

## 頁面結構

### 1. 總覽

顯示：

- 線上節點數
- Broker client 數量
- 雲端設備數
- 雲端群組數
- API 金鑰數量
- 最近事件

總覽頁只顯示摘要，不顯示原始 JSON。

### 2. 繼電器

主要內容：

- 節點與群組選擇
- 16 路 Relay 卡片
- 單路開 / 關
- 全部開 / 全部關
- 強制停止
- 單路設定

Relay 卡片上應保留：

- 名稱
- 開啟 / 關閉狀態
- 排程狀態
- 處理中狀態

### 3. 排程器

主要內容：

- 節點與通道選擇
- 排程啟用 / 停用
- 暫停 / 恢復
- 7 天排程卡片
- 單日新增 / 刪除 / 清空
- 單日複製
- 整週複製到其他通道

排程器頁面的顯示方式要接近 MCU Web，而不是只用很大的下拉選單。

### 4. 保護

主要內容：

- 全域保護參數
- 每路保護狀態
- CT 是否就緒
- 學習狀態
- 策略狀態
- 強制停止 / 清除學習 / 切換策略

保護頁面要避免把「CT 未就緒」顯示成 0 mA。

### 5. 節點

主要內容：

- 節點清單
- 群組
- 線上狀態
- Relay mask
- 最後上報時間

### 6. 雲端

主要內容：

- 認領節點
- 雲端群組列表
- 雲端設備列表
- 指紋重設
- CA 旋轉
- 套用線上節點

### 7. 金鑰

主要內容：

- 建立 API 金鑰
- 啟用 / 停用
- 刪除

### 8. 事件

主要內容：

- 事件名稱
- 時間
- 摘要

不要直接顯示整包 JSON。

## 寫入流程原則

所有會改變 MCU 狀態的動作，都應遵守：

1. UI 先進入處理中狀態。
2. 後端送出 MQTT command。
3. 等待 ack 或完成回應。
4. 成功後再恢復顏色與可操作狀態。
5. 失敗時顯示明確錯誤，不要假裝成功。

## 低頻快取原則

後端管理台不應該在每次 render 時都重新打同一批 API。

建議策略：

- 總覽資料：SSE 為主，輪詢為輔。
- Relay / 保護 / 排程器：只查目前選中的節點與通道。
- 同一份資料使用短 TTL 快取，避免重複送出。

## 版面規範

- 同一排按鈕必須對齊。
- 卡片要能換行，不可因為字多就爆版。
- 行動版要改成單欄或雙欄排列。
- 所有 i icon 都要附上說明文字或 title。
